# Simulated demo datasets: SYNTHETIC, not patient data

> [!WARNING]
> Everything under this directory is **synthetic**. It was generated by
> [`scripts/synthetic_demo.py`](../../scripts/synthetic_demo.py) (generator version 0.1, seed 0). It is
> for testing pipelines and for tutorials only. It describes no one, and it is not derived from any
> credentialed dataset, so it carries no clinical signal. **Do not use it for research.**

MIMIC-IV-Note, MIMIC-CXR, MIMIC-CXR-JPG and MIMIC-IV-ECHO are credentialed PhysioNet projects with no
public demo. Without one, a `dataset_key=demo` build of any spec that reads them has nothing to
read. This directory simulates each of them for the 100 subjects of the public
[MIMIC-IV Clinical Database Demo 2.2](https://physionet.org/content/mimic-iv-demo/2.2/). The
simulated rows use the demo's real `subject_id`s, `hadm_id`s, admission, ED and ICU times, and
provider ids, and each module is laid out exactly as its release is: file names, columns,
delimiters and compression.

The modules are simulated together, so they agree with each other:

- every demo admission has a discharge summary, charted at its `dischtime` and stored later;
- radiology reports fall inside admissions, ED visits and ICU stays, or before any stay with no
    `hadm_id`;
- every chest X-ray report is a MIMIC-CXR study. Its report file has the same text, its images are
    taken at the report's `charttime`, and its CheXpert labels are the findings the report states;
- echocardiograms fall inside some admissions and after others;
- the simulated MIMIC-Note-Extract (MNE) tables are extracted from the simulated discharge summaries
    (their structured content), plus one summary for an admission that is not in MIMIC, as the real
    MNE has.
- the simulated MIMIC-CXR-DB tables are derived from the simulated MIMIC-CXR(-JPG) images and labels and the concepts the simulated reports and discharge summaries mention, plus one subject, study and admission that exist nowhere else, as the real release has.

### Where the public documentation stops

These are documented nowhere public, so the simulation makes a choice and says so here:

- **`cxr-record-list` columns.** The docs list `subject_id`, `study_id` and `dicom_id`, and those are
    the columns here. If the release has more columns, the docs do not say so.
- **`cxr-provider-list` column names.** These are the four names the PhysioNet page gives:
    `study_id`, `ordering`, `attending` and `provider`. Provider ids are drawn from the demo's
    `hosp/provider`.
- **Column order of the ECHO lists.** The ECHO page names the columns but does not give their
    order.
- **ECHO note links.** `note_id`, `note_seq` and `note_charttime` are empty. The cardiologist reports
    they would link to are not in MIMIC-IV-Note 2.2, and the format of their ids is not documented.
- **ECHO machine measurements.** These are not part of 0.1; the page says they "will be released in
    an upcoming version". There is no measurement table to simulate.
- **Radiology `exam_code`.** Real exam codes are internal hospital codes and their format is not
    documented. The simulated ones are `SYN01`, `SYN02`, and so on. Exam names follow the chest
    X-ray names the CXR-JPG page quotes. CPT codes are the public procedure codes for those exams.
- **Discharge `charttime`.** It is set to the admission's `dischtime`; `storetime` is 30 min to 48 h
    later.
- **MIMIC-CXR-DB.** The project page does not give the column order, the semicolon delimiter, or the `_jev` tables' `id`, `label` and `class` columns. Those follow this repository's `extensions/cxr_db.yaml` and `MIMIC_IV_MEDS.prepare_cxr_db`. The `relation_type` values used (`FINDINGS`, `IMPRESSION`, `Past Medical History`, `Laboratory and Results.Discharge Labs`) are section names of the simulated notes.
- **Order of the label columns.** The 14 CheXpert columns follow the order the CXR-JPG page lists.

### What is not simulated

- **Images.** No DICOM or JPG files are included, only the lists and metadata that describe them
    (`IMAGE_FILENAMES` names files that are not here). No spec in this repository reads pixels. A
    placeholder image would cost a few hundred bytes, but it would add hundreds of files that no
    image model can use. And a consumer that opens images must already handle missing files, which
    is what `IMAGE_FILENAMES` is for (partial downloads). The same applies to the ECHO DICOMs.
- **`mimic-cxr-reports.zip`.** It is a convenience archive of the same `.txt` files.
- **Modules with a public release.** The MIMIC-IV demo (hosp, icu) and the
    [MIMIC-IV-ED demo](https://physionet.org/content/mimic-iv-ed-demo/2.2/) are public. So are
    [MIMIC-IV-ECG](https://physionet.org/content/mimic-iv-ecg/1.0/) (with its own
    [demo](https://physionet.org/content/mimic-iv-ecg-demo/)) and the
    [MIMIC-IV Waveform Database](https://physionet.org/content/mimic4wdb/0.1.0/), which are open
    access.

## How the values are made

Nothing is read, sampled or fitted from any credentialed dataset. That includes values,
distributions, category frequencies and even file headers. The inputs are:

- the public demo's `hosp/admissions`, `hosp/patients`, `hosp/provider` and `icu/icustays`;
- the schemas above;
- public vocabularies:
    - SNOMED CT concepts for history and chest findings, each id checked against the HL7 terminology
        server [tx.fhir.org](https://tx.fhir.org);
    - LOINC codes for discharge labs, checked against the NLM LOINC API;
    - the CheXpert label names;
    - common generic drug names and drug-allergy classes;
- the closed enums of [MIMIC-Note-Extract's public data dictionary](https://physionet.org/content/mimic-iv-ext-note-extract/1.0/)
    for the structure of the discharge summaries, so that a simulated MNE can be derived from them.

All free text is a template that says it is synthetic. Each note starts with
`SYNTHETIC ... - NOT REAL PATIENT DATA - FOR PIPELINE TESTING ONLY`, and the sentences read like
"Synthetic history of present illness sentence 2." Every probability in the generator is an
arbitrary round number chosen to cover each case, not an estimate of anything.

## Using it

`sources.yaml` lists, for each module, an `http` source that fetches these files from GitHub at a
fixed commit, with each file's SHA-256. Copy it into a spec's `demo` bucket, and set that bucket's
`dataset_version` to the module's, so that `meds-extract-run spec=... dataset_key=demo` fetches
everything in one step.

To change the data:

```bash
uv run python scripts/synthetic_demo.py generate --demo-dir $DEMO  # $DEMO: the public demo download
# commit and push the regenerated files, then pin to that commit:
uv run python scripts/synthetic_demo.py pin --ref <commit>
```

`tests/synthetic_demo_test.py` fails if the files are stale or hand-edited, if the pin is stale, or
if the modules stop agreeing with each other or with the demo.
